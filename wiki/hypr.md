# hypr

The compositor. Keymap — [keymap](keymap.md), colors — [theming](theming.md),
terminal — [kitty](kitty.md) / [sessions](sessions.md).

## Key decisions

- **Config is Lua (`hyprland.lua`); `hyprland.conf` is dead weight.** Since
  Hyprland 0.55 hyprlang is deprecated. If `hyprland.lua` exists it wins, and
  that check happens once at startup — so the old `.conf`, and anything it
  `source`s, is never read. ⚠️ Gotcha: `--verify-config` is lenient about
  window-rule *value types* and accepts the old `size = "95% 95%"` /
  `center = 1` forms, which Lua then rejects at runtime (it wants
  `size = {"95%","95%"}` and `center = true`). The truth is in
  `/usr/share/hypr/stubs/hl.meta.lua`, autogenerated for the installed version.
- **`hyprctl dispatch` now evaluates its args as Lua.** The legacy form
  (`hyprctl dispatch workspace 3`, `killactive`, `dpms`) fails with a syntax
  error, which in a script, kanata action, or waybar button is a **silent
  no-op**. All repo call sites use `hl.dsp.*`. ⚠️ This is why waybar must be
  `waybar-git` — the 0.15.0 release still emits legacy dispatches, so clicking
  a workspace does nothing ([waybar](waybar.md)).
- **OpenWhispr's own bind file is inert.** `openwhispr-binds.conf` was deleted
  in 2026-08-03 because only `hyprland.conf` sourced it. The app may recreate
  it; those rewrites have no effect. The inline `CTRL, Super_L` bind in
  `hyprland.lua` is the single source of truth — if OpenWhispr's binding
  changes, copy it over by hand.
- **`SUPER+Return` routes through `kitty-new-window.sh`, not a bare `exec
  kitty`.** A bare launch starts an independent kitty process with no source
  window, so its tabs never get tagged into a session — see the orphan-process
  gotcha in [sessions](sessions.md). The login `hl.on("hyprland.start", ...)`
  hook stays a bare `exec` on purpose: no main kitty exists yet to attach to.
- **`no_hardware_cursors = true`** works around an invisible/corrupted cursor on
  this hardware. Not cosmetic — don't remove it as cleanup.
- **`kb_layout = us,ru`, but kanata drives the switching**, not Hyprland; only
  the two layouts are registered here. `hyprland-per-window-layout` runs on top.
  See [kanata](kanata.md), [keymap](keymap.md).

## Autostart

⚠️ Gotcha: **the browser is deliberately not in `exec-once`** (removed in
`75f46cf`). Helium comes up lazily via
`workspace = 2, on-created-empty:helium-browser` when workspace 2 is first
entered. Its measured Hyprland class is `helium`, which is what the browser
helpers in [scripts-pickers](scripts-pickers.md) match on.

kanata is **not** started here either — it moved to a systemd user service
(`../systemd/user/kanata.service`) so it survives compositor restarts and
restarts on crash.

### `openwhispr` must be prefixed with a `busctl` call

OpenWhispr keeps its session token encrypted with a master key in the OS keyring
(Secret Service). Without the key it falls back to `safeStorage`, `decrypt()`
throws `decryption failed: no backend available`, and **the app shows its login
screen on every boot**.

Secret Service here is KWallet, and `org.freedesktop.secrets` is **not** a
D-Bus-activatable name — only `org.kde.secretservicecompat` is; `ksecretd`
registers the former only once started under the latter:

```lua
hl.exec_cmd(
  "busctl --user call org.freedesktop.DBus /org/freedesktop/DBus "
    .. "org.freedesktop.DBus StartServiceByName su org.kde.secretservicecompat 0 "
    .. "&& openwhispr"
)
```

⚠️ The `&&` is load-bearing: `exec_cmd` gives no ordering between separate
calls, so activation and launch must be one command. `busctl` (unlike
`dbus-send`) waits for the service before returning.

⚠️ **`pam_kwallet5` does NOT work here — don't reintroduce it.** It was tried
first and failed for two compounding reasons: `getty@tty1` runs
`agetty --autologin`, so the session isn't graphical yet when `login` runs
(`not a graphical session, skipping`; `force_run` silences that but fixes
nothing), and — structurally — autologin means PAM's `auth` stack never captures
a password for it to relay (`open_session called without kwallet5_key`). This is
a dead end for **any** autologin setup, not a config to keep tuning.

The actual fix: the `Default keyring` wallet password was set to **empty**, so
`ksecretd` opens it unprompted. The root filesystem is plain ext4 with no LUKS,
so the password was guarding only a narrow snapshot-theft scenario at the cost
of a login prompt every boot. Note the wallet also holds Chromium `Safe Storage`
keys and the `copilot-language-server` OAuth token — with an empty password
those rest on file permissions (`0600`) alone.

Verify after a cold boot: `busctl --user list | grep org.freedesktop.secrets`
and `secret-tool search service OpenWhispr` (should return the entry with no
prompt).

## Session launch: uwsm

Hyprland starts via `uwsm start hyprland-uwsm.desktop` from `../zsh/zprofile`,
not the raw binary, because Hyprland never activates `graphical-session.target`
itself — without uwsm the systemd user manager never learns `WAYLAND_DISPLAY`,
and user services needing the session start with a broken environment.

⚠️ Gotcha: uwsm only protects services that **order themselves after**
`graphical-session.target`. A `WantedBy=default.target` unit with no `After=`
can start in the same instant `default.target` is reached and race uwsm's
environment import. `copyq.service` did exactly this — crash-looping on "no Qt
platform plugin" until it hit systemd's start limit — until
`After=graphical-session.target` was added. Any user service touching the
Wayland session needs that line, not just `WantedBy=`.

## Bindings worth knowing about

Full map in [keymap](keymap.md); only the surprises here.

- `SUPER, Q` (killactive) is **commented out** — it's wired through kanata's
  apps layer instead, where Q sits under the thumb.
- **`Ctrl-h/j/k/l` is not a Hyprland binding at all** — it lives in kitty via
  `pass_keys.py`, which gives nvim and fzf first refusal ([kitty](kitty.md)).
- `SUPER, N` opens the self-pasting scratch note — a QAT panel, deliberately not
  a special workspace or windowrule ([scripts-scratch](scripts-scratch.md)).

## idle / lock

hypridle has exactly **one** active listener: 30 min → `systemctl suspend`.
Dimming, dpms-off and an early lock are commented out on purpose.
`before_sleep_cmd = loginctl lock-session` guarantees the lock happens *before*
sleep rather than racing it.

## Env, Qt, and HiDPI

`QT_QPA_PLATFORM = wayland` is global, so Qt apps get native Wayland — the
laptop panel runs at fractional scale `1.6`, and XWayland would just upscale a
1x buffer. Two apps are deliberate exceptions: `copyq` (alias forces xcb, may
look soft) and `sioyek`, which is pinned to XWayland by a wrapper for a much
harder reason — its Qt6 cannot create an EGL context on nvidia under Wayland at
all ([sioyek](sioyek.md)).

### Fractional scaling on the laptop panel

XWayland can't do fractional scaling, so `xwayland = { force_zero_scaling =
true }` leaves those surfaces unscaled and crisp, and each toolkit scales
itself:

- **Qt/X11 apps that ignore Wayland** (Happ bundles its own Qt and forces xcb):
  `QT_SCALE_FACTOR=1.6` set **per-app** in a local `.desktop` override — a
  global one would double-scale Wayland-native Qt apps.
- **fyne/GLFW apps** (adrop has no Wayland backend at all): `FYNE_SCALE=1.6`.
- GTK X11 apps would need `GDK_SCALE`.

⚠️ Gotcha: `QT_QPA_PLATFORM=wayland` is not a guarantee — Happ still renders via
XWayland. Verify with `hyprctl clients` (`xwayland: true`) and don't chase why;
force xcb plus `QT_SCALE_FACTOR` in the `.desktop`.
